# jarvis-pyqt — Full Code Audit (2026-11-12)

Read-only audit. No code was changed. Static analysis (ruff, bandit), the repo's own
pytest suite, git-history secret scan, and 5 parallel deep-dives (data/SQL, agent/LLM,
audio, GUI/UX, project hygiene). Every finding cites file:line; high-rated claims were
re-verified by hand after the sub-audits.

Repo: 18 source files, ~8.7k LOC under src/, 23 test files, 5 SQL scripts.

---

## 1. The verification gate is broken (why "weird things" went unnoticed)

**The test suite does not run in any headless/CI environment — and by default it reports
success anyway.**

- `pytest tests/` **aborts at collection** with 6 import errors — 0 tests execute.
- With `--continue-on-collection-errors`: **142 passed, 14 failed, 19 errors**.
- Root cause (systemic, not flaky): `src/jarvis/__init__.py:10` eagerly imports
  `hud_overlay` → `PyQt6.QtGui`, so *every* test that touches `jarvis.*` — even pure
  logic like face/config — dies on `libEGL.so.1` missing (any GPU-less Linux/CI box).
  Tests were clearly written on macOS where PyQt always imports.
- `pytest-qt` is in `requirements-dev.txt` but **not installed in the repo's own venv**
  → `qtbot` fixture missing (9 errors).
- `pyproject.toml:48` sets `qt_api = "pyqt6"` — pytest warns "Unknown config option"
  because the plugin never loads. Dead config.

**Fix (highest leverage):** make `src/jarvis/__init__.py` lazy (or import-free), install
pytest-qt into the venv, and add a GitHub Action running
`QT_QPA_PLATFORM=offscreen pytest` — then this class of silent breakage stops.

Static gates: ruff → 54 issues (F841 unused var, B007, 2 unused imports, rest mostly
style); bandit → 21 low-severity items (verified below). Nothing catastrophic in the
linting itself — the problem is nobody runs any of it.

## 2. Security findings (verified)

### S1. Real LAN credentials committed — CRITICAL
`.env.template` lines 9/14 (commit `9f69cd3`, in history) contain the **real** MariaDB
root password for 192.168.55.41 and the live `freellmapi-…` gateway API key — not
placeholders. If the repo is ever pushed anywhere public (or was), rotate both and
purge history (`git-filter-repo`). A `.env.template` should contain `changeme` values.

### S2. Per-profile LLM API keys stored plaintext in MariaDB — MEDIUM
`sql/004_add_api_key_to_profiles.sql:10`: `api_key VARCHAR(255) NOT NULL DEFAULT ''`.
Write/read path in `profile.py` stores it unencrypted. The app itself keeps app-level
secrets in macOS Keychain (config.py `_keychain_store_secret` — good), but the DB
column has no protection. Anyone with DB read access gets every profile's key.

### S3. Hardcoded LAN IPs and hostnames as code defaults — MEDIUM
`config.py` dataclass defaults (~166–183): `db_host="192.168.55.41"`,
`llm_base_url="http://192.168.55.179:8642/v1"`, STT/TTS hosts. Brittle off-LAN, and
leaks infrastructure in any shared copy. Tests show the fallback drift: captured logs
show `Can't connect to MySQL server on 'localhost'` during test runs.

Good news on bandit's subprocess hits (config.py:38/67/116): they invoke macOS
`security` (Keychain) with argument lists, no `shell=True`, no user input → **not
injectable** (verified, downgraded from bandit's noise).

SQL injection: **clean.** All queries in profile.py/face.py/settings.py use pymysql
`%s` parameterization; no f-string SQL found.

## 3. Correctness / reliability bugs (verified)

### B1. Qt thread-affinity violations — HIGH (verified by hand)
`wake_word.py:_callback` (PortAudio thread) → `on_wake()` → `agent._on_wake_word()`
(agent.py:446-455) calls **`self.hud.set_state(...)` directly on the audio thread**.
Qt widgets may only be touched from the GUI thread; this is undefined behavior
(occasional crash/corruption, timing-dependent — a classic "weird thing"). Same shape
in `barge_in.py:94-116` → `agent.interrupt()` → audio.stop()/UI ops from the PortAudio
thread. Fix: marshal via Qt signal (queued) or `QMetaObject.invokeMethod`.

### B2. Voice cycle has no overall timeout — HIGH
`agent._run_voice()` (497-594): if the STT/TTS/LLM TCP connection hangs (not refused,
*hung*), the cycle waits forever — `stt.listen()`'s timeout only covers silence
detection, `tts.speak()` has none. The app sits in LISTENING/THINKING with no way out
except STOP. Wrap with `asyncio.wait_for` + surface the failure.

### B3. Approval-card system is dead code — MEDIUM (verified: grep confirms)
`agent.request_approval()` (247-274) and the HUD `ApprovalCard` (hud_panels.py:151+)
exist, wired into main.py:562-569 — but **no code path ever calls `request_approval`**.
Today the UI shows "approval" affordances for nothing. Either wire real gated actions
through it or delete it. (This also means: LLM output currently **cannot** execute
anything locally — `on_tool_call` is display-only. That part is safe.)

### B4. Unbounded conversation history — MEDIUM
`agent._messages` (agent.py:181, 511, 614) grows forever; per-profile
`chat_history` persists unbounded in MariaDB. Eventually exceeds the model context and
the request 4xx's — after weeks of use this is a guaranteed slow-burn bug. Need a
sliding window / token budget / rolling summary.

### B5. Barge-in race — MEDIUM
agent.py:588-594: interrupt landing between `tts.speak()` returning and
`audio.play()` starting still plays the sentence (stop-flag checked before play, not
under the same lock). Small window, real annoyance when interrupting.

### B6. DB connection without ping/reconnect — LOW
`profile.py:161-170`: single pymysql connection, no `ping(reconnect=True)`. A MariaDB
restart kills profile/face features until app restart. (Graceful at startup — good.)

### B7. aiohttp chat session: no retry/backoff on 401/429/drop — LOW-MED
`chat.py:36-48` reuses one session; errors return `None` silently (90-103). No
circuit-breaker; stale-auth sessions persist.

### B8. Schema drift between SQL files and code — LOW
`create_profiles_table.sql` includes `api_key` but **misses `face_name`** (migration
003); `face.py` creates `face_model` with `name` as PK while the .sql uses an
AUTO_INCREMENT id. Two sources of truth (plus face.py:105-123 inline DDL). Fresh
installs from the base script get a different schema than migrated ones.

### B9. Wake-word model loaded in `__init__` — LOW
`wake_word.py:55-60`: openwakeword ONNX load happens at construction, delaying
startup; degrades to push-to-talk if missing (good fallback). Lazy-load it.

## 4. GUI / UX — why it feels "not up to standard" (verified)

**U1. Everything is hardcoded-pixel, zero DPI awareness.** `main.py:399`
`self.resize(800, 600)`, `hud_overlay.py:56` `self.resize(800, 600)`, fixed 40×40 /
34×34 / 35×35 buttons (main.py:426-507), fonts by fixed point size. On a HiDPI or
4K screen the HUD renders tiny and blurry; on small screens panels overflow.
→ Use logical coordinates + `devicePixelRatio` scaling (or Qt::AA_EnableHighDpiScaling
consistently), size from screen geometry, scale fonts.

**U2. Vague error UX — the app almost never tells you what's wrong.** LLM down →
status label flips to `✗ Error` (main.py:940-942). STT/TTS down → `⚠ Partial
connection` (main.py:577) with no indication *which* service, why, or that Settings
can fix it. DB down → log line only. There's no persistent health/connection panel.
→ A small connection-status strip (STT / TTS / LLM / DB: green-amber-red, click →
Settings) would remove most user confusion.

**U3. No startup health gate.** App boots with services unreachable and looks
"working" until the first voice/text command silently fails. → Probe STT/TTS/LLM/DB at
startup and show an onboarding banner with the exact host:port failing.

**U4. Keyboard/accessibility minimal.** One shortcut (F2). No Space=push-to-talk,
Esc=stop, no focus traversal polish, no accessible names on icon buttons. → Add
shortcut map + `setAccessibleName` on buttons.

**U5. settings.py is a 1,494-line god-object** mixing tabs, DB test logic, and config
persistence — which is also why `test_settings.py` can't even import. → Split
UI/persistence/test-connection. Not user-visible, but it's the maintenance ceiling.

**U6. Animation CPU/consistency:** 60fps QTimer repaint of the full HUD
(hud_overlay) + 30fps smoke face with *frame-count-based* (not time-based) animation;
timers keep running while idle. → time-delta animation; idle rate drop; pause when
occluded.

**U7. Face-recognition UX:** enrollment quality gating exists (blur/brightness —
good) but no camera-in-use/no-camera error surfaced; confidence thresholds fixed;
no "enrollment progress" indicator (N more samples needed).

## 5. Project hygiene

- **Unpinned `requirements.txt`** vs semver ranges in `pyproject.toml` — two sources,
  inconsistent (wake-word deps optional in one, required in the other). Pick one.
- **No CI at all** — with the import bug (Finding 1), nothing would have caught this.
- `.gitignore` correct (no secrets or .pytest_cache *tracked* — `.pytest_cache` dirs
  on disk are untracked cruft; history scan found **no other leaked files** ever added).
- run_jarvis.sh: plain launcher, no QT env handling — fine locally, hostile to CI.

## Strengths (real, verified)
- All SQL parameterized; subprocess calls safe; secrets *app-level* go to macOS
  Keychain with placeholder filtering — thoughtful.
- Correct asyncio architecture: agent on an event-loop QThread, Qt signals bridging,
  chunked interruptible playback, correct Wyoming protocol framing, graceful
  degradation when mic/models missing, clean `close()` paths.
- 142 tests that *do* pass are genuinely substantive (streaming, barge-in, wakeword
  gating, profile switch), not import-only mocks.

## Rejected / downgraded sub-audit claims (audit-of-the-audit)
- "No LLM-driven code execution is high-severity risk" → verified: tool_call is
  HUD-display only; no exec path exists. Reframed as finding B3 (dead approval code).
- bandit B311 `random.*` (HUD particles/visemes) → cosmetic animation, not security.
- bandit B105 "hardcoded password" strings → are keychain *key names*, false positives.
- "Window cannot be resized" → not substantiated; `resize()` sets initial size only.
- "settings.py is critical" → real problem, but rated MEDIUM (maintainability, not a
  runtime defect).

5. History truncation (B4); then schema consolidation (B8), DPI scaling (U1).
